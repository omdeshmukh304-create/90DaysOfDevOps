# Task 1: Understand Observability

## 1. What is observability? How is it different from traditional monitoring?

### Monitoring

Monitoring tells us **when something is wrong**.

Examples:

* CPU usage above 90%
* Disk space below 10%
* Application is down

Monitoring is generally based on predefined alerts and thresholds.

### Observability

Observability helps us understand **why something is wrong**.

It allows engineers to investigate system behavior by analyzing metrics, logs, and traces.

### Difference

| Monitoring                    | Observability                        |
| ----------------------------- | ------------------------------------ |
| Tells when something is wrong | Tells why something is wrong         |
| Based on predefined alerts    | Allows exploration and investigation |
| Reactive                      | Investigative                        |

---

## 2. The Three Pillars of Observability

### Metrics

Numerical measurements collected over time.

Examples:

* CPU usage
* Memory usage
* Request count
* Error rate

Tools:

* Prometheus
* Datadog
* AWS CloudWatch

---

### Logs

Timestamped records of events generated by systems and applications.

Examples:

* Application logs
* Error messages
* Access logs

Tools:

* Loki
* ELK Stack
* Fluentd

---

### Traces

Track the complete journey of a request across services.

Examples:

* API requests
* Microservice communication
* Database calls

Tools:

* OpenTelemetry
* Jaeger
* Zipkin

---

## 3. Why DevOps Engineers Need All Three

Metrics tell us **what** is wrong.

Logs tell us **why** it is wrong.

Traces tell us **where** it is wrong.

Example:

* Metrics show high error rate.
* Logs show database timeout.
* Traces identify the exact service causing delays.

# Task 2: Set Up Prometheus with Docker

## docker-compose.yml

```yaml
services:
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus

    ports:
      - "9090:9090"

    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
      - prometheus_data:/prometheus

    command:
      - "--config.file=/etc/prometheus/prometheus.yml"
      - "--storage.tsdb.retention.time=30d"
      - "--storage.tsdb.retention.size=1GB"

    restart: unless-stopped

  notes-app:
    image: trainwithshubham/notes-app:latest
    container_name: notes-app

    ports:
      - "8000:8000"

    restart: unless-stopped

volumes:
  prometheus_data:
```

---

## prometheus.yml

```yaml
scrape_configs:
  - job_name: "prometheus"
    static_configs:
      - targets: ["prometheus:9090"]

  - job_name: "notes-app"
    static_configs:
      - targets: ["notes-app:8000"]
```

# Task 3: Understand Prometheus Concepts

## Scrape Targets

Endpoints from which Prometheus collects metrics.

Examples:

* prometheus:9090
* notes-app:8000
* node-exporter:9100

Prometheus uses a pull-based model and scrapes metrics at regular intervals.

---

## Metric Types

### Counter

Only increases.

Examples:

* Total requests
* Total logins
* Total errors

---

### Gauge

Can increase or decrease.

Examples:

* CPU usage
* Memory usage
* Active connections

---

### Histogram

Stores observations in buckets.

Example:

* Request duration

Buckets:

* <100ms
* <500ms
* <1s

---

### Summary

Calculates percentiles.

Examples:

* p95 latency
* p99 latency

---

## Labels

Labels add dimensions to metrics.

Example:

```text
http_requests_total{method="GET",status="200"}
```

---

## Time Series

A unique combination of:

```text
Metric Name + Labels
```

Example:

```text
http_requests_total{method="GET",status="200"}
```

# Task 6: Explore Data Retention and Storage

## Storage Usage

Command:

```bash
docker exec prometheus du -sh /prometheus
```

Output:

```text
1.0M /prometheus
```

---

## Retention Configuration

```yaml
command:
  - "--config.file=/etc/prometheus/prometheus.yml"
  - "--storage.tsdb.retention.time=30d"
  - "--storage.tsdb.retention.size=1GB"
```

---

## What Happens When Retention Is Exceeded?

Prometheus automatically deletes the oldest TSDB blocks when:

* Retention time is exceeded
* Storage size exceeds configured limits

This prevents storage exhaustion.

---

## Why Is a Volume Mount Important?

Prometheus stores all metric data in:

```text
/prometheus
```

Using:

```yaml
volumes:
  - prometheus_data:/prometheus
```

ensures historical metrics survive:

* Container restarts
* Container recreation
* Upgrades

Without a volume, all metric history would be lost when the container is removed.
